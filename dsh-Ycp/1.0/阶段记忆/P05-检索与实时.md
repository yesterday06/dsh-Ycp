## 做了什么

- **检索打分**（`src/host/organs/search.js`）：
  - 标题 / 文件名命中 **×3**，tags 命中 **×2**，正文命中 **×1**；
  - 中文按二元组切、英文/数字按整词切；同一 token 在同一区域只算一次，长文刷不上分；
  - 同分按修改时间新的在前。
- **取 top-k**：默认 2，可在 `settings.json` 改（1–5）。
- **单卡截断**：默认 600 字（100–2000），截断带省略号；先去掉 frontmatter 和首个标题行。
- **实时卡必读**：不管问什么，实时记忆里的卡都带上（每张最多 200 字），标注为「此刻：」。
- **日记不参与**：只检索全局 + 归档；日记内容永远进不了 system。
- **拼进 system**：在「你的名字」之后、「当下」之前加一段：
  ```
  【你记得的】
  - 篮球：周末去打篮球，球场在东边。
  - 此刻：正在看球赛。
  ```
  什么都没命中就整段省略，省 token。
- **接口**：`GET /api/dsh-Ycp/memory/search?q=&topK=&maxChars=`（调试/验证用）；`/say` 返回值多一个 `recalled`，面板回复下方会显示「想起：篮球」。
- **设置**：新增 `memoryTopK`（默认 2）、`memoryMaxChars`（默认 600），读写时校验范围。

## 坑

- **实时卡让「没命中也有记忆段」**：只要实时目录里有卡，system 就会有「你记得的」；自检里想断言「整段省略」必须先删掉实时卡。
- **topK / maxChars 要跟设置校验对齐**：设置读的时候会夹范围，接口参数没夹——`search()` 内部自己做了下限保护，但传负数会变成默认值，别指望它报错。
- **截断测试别用热门词**：用「篮球」测截断会选中标题命中那张短卡，看起来像没截断；要造一张唯一词的超长卡。
- **截断按字符不按 token**：600 字中文约 600 token 上下，已经够省；真嫌贵再调 `memoryMaxChars`。
