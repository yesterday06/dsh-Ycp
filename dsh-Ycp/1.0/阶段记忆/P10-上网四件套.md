## 做了什么

- **四个工具**（`src/host/capabilities/web.js`），挂进 P09 的注册表：
  | 工具 | 干什么 | 权限 |
  |---|---|---|
  | `web.search` | 走宿主 `ctx.web.search`，返回标题 / 链接 / 摘要 | `webSearch` |
  | `web.fetch` | 走宿主 `ctx.web.fetch`，HTML 去标签、取标题，只收 http/https | `webFetch` |
  | `memory.remember` | 写一张全局记忆卡（frontmatter 自动生成，同名覆盖前备份） | `memoryWrite` |
  | `memory.recall` | 用 P05 的检索找卡，返回标题与摘要 | `memoryRead` |
- **权限开关**：`settings.permissions` 四个布尔值，注册表在 `invoke` 入口统一检查；关掉直接 `permission` 拒绝，根本不会碰宿主服务。
- **统计联动**：查 / 读成功 → 体力 −1、「今天查网」+1。
- **面板**：`手` 区多四个权限开关（点一下切换，立即生效），工具列表自动多出四条。
- **错误如实上报**：搜索没有 key 时，把宿主原话（`DeepSeek search has no API key…`）带回工具结果，不伪造"没找到"。

## 坑

- **宿主的 `web` 是服务不是工具**：`ctx.get('web')` 可选读取，没注册 provider 时会抛 `WEB_PROVIDER_UNAVAILABLE`；别在插件加载时断言它存在，否则没配 key 的环境直接起不来。
- **权限检查要在注册表入口**：四个工具都声明 `permission`，由 `invoke` 统一挡；工具自己再查一遍会重复且容易漏。
- **fetch 返回非 2xx 是结果不是异常**：宿主约定如此，工具照实报 `status`，别把 404 当调用失败。
- **HTML 去标签故意很粗**：`<script>/<style>` 先整段删，再删标签、还原几个实体；真需要结构化解析等 P11 用浏览器时再说。
- **测试断言别覆盖演示工具**：`demo.*` 本来就没有 permission，断言"每个工具都带权限"会误伤。
