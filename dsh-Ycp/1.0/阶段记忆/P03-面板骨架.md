## 做了什么

- **面板三块**：
  - 状态行：模型（provider/model）、人设字数、上次说话时间、状态灯（能说话 / 还不会说话 / 未连接）。
  - 她的人设：textarea 直接改，`保存人设` 落盘，`恢复默认` 把默认人设填回（要再点保存才生效），实时字数。
  - 试说一句：输入 + `让她回`，回车也能发；回复气泡带「名字：」、模型、耗时、时间；失败把原因写在原地。
- **`POST /api/dsh-Ycp/say`**：
  - 模型跟随当前对话（`agentDefaultModel.currentSelection()`），不另配 key、不读环境变量。
  - system 顺序固定：`【人设】全文` → `【你的名字】` → `【当下】`（日期/时段/工作日周末 + 「不必刻意报时」）。
  - `ctx.llm.stream()` 收 `text-delta` 拼一句话；60 秒超时；终止块里的真实失败原因直接回给面板，不编文案。
  - 只有模型声明支持 `off` 时才传 `reasoningEffort: 'off'`，闲聊不花推理钱；不支持就省略。
- **`GET /persona` 多返回一份默认人设**，给「恢复默认」用。
- 状态接口多返回 `model`，面板不用自己猜。
- 设置（名字 / 启用）挪到面板下方，P02 的能力没丢。

## 坑

- **消息不用 dsh-llm 的构造器**：`llm.stream` 的 `messages` 接受 `{role:'user', content:[{type:'text',text}]}`（RequestUserInput），不必 import `createUserMessage`，插件保持零依赖。
- **`reasoningEffort: 'off'` 不能乱传**：模型没有 reasoning 元数据时会被判 `UNSUPPORTED_REASONING_EFFORT`，表现是空流「模型没说话」。必须先 `resolveModelInfo` 查 efforts 里有没有 `off`。
- **`sessionId` 要带**：某些服务商（opencode-go）靠它生成请求头，缺了回 400。固定传 `'dsh-Ycp'`。
- **空流不等于成功**：`finish` 块里可能是 `error`，要把 `failure.message` 原样带回面板，别显示「模型没说话」。
- **临时 profile 有默认模型但没有 key**：`/say` 报的是 `no API key`，这是环境事实，不是插件 bug。装到 desktop profile 后才有凭据。
- **超时别设太短**：推理模型首字慢，60 秒是下限；面板侧只显示「她在想…」，不阻塞其它操作。
